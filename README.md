# CGF_Final_Project

**Topic 15: 2.5D castle with parallax occlusion on walls**
Срок отправки: **14 ноября 2026**.

Команда: Akezhan Muzamelov, Bolatbek Bolat, Adil Dyussenov.

## Что уже есть и что осталось

| Требование задания | Статус |
| --- | --- |
| 2.5D-замок, который можно исследовать | Большой холл (60 × 40 × 216 м, 24 колонны) и фасад со стрельчатым входом |
| Фасад с ощущением интерьера | Через арку фасада виден зал с колоннами |
| Parallax occlusion mapping на стенах | **Не сделано** — следующий этап |
| Карта высот для POM | `assets/textures/stone_wall/height.png` лежит в проекте, в шейдере пока не используется |
| Боковой свет, на котором видно самозатенение POM | Не сделано |
| Взаимодействие (ключ / знамя / ворота) | Не сделано; рыцарь пока — простая модель для масштаба |

Атмосфера: холодная палитра, туман по глубине, тёплая люстра, лучи из окон.
Направление сцены — в `docs/SCENE_DIRECTION.md`, подробности холла и
управление — в `docs/HALL_CONTROLS.md`.

## Первый запуск в Visual Studio

1. Нужна Visual Studio с компонентами **«Разработка классических приложений
   на C++»** и **«Средства CMake C++ для Windows»**. Нужны CMake 3.24 или новее
   и видеодрайвер с поддержкой OpenGL 3.3.
2. Клонируй репозиторий и открой его папку через **File → Open → Folder**.
   Открывать нужно папку, в которой находятся `CMakeLists.txt` и
   `CMakePresets.json`.
3. Выбери конфигурацию **windows-debug / Windows x64 Debug**. Если после
   добавления presets она ещё не появилась, закрой и снова открой папку.
4. Дождись завершения настройки CMake. При первой настройке CMake скачает
   GLFW и GLM с GitHub; нужен интернет. GLAD уже включён в исходники.
5. Выбери цель запуска **simple_castle.exe** и нажми **Ctrl+F5**.

Вручную прописывать include-пути, подключать `.lib` или устанавливать vcpkg
для этого проекта не нужно. `windows-release` предназначен для сборки
с оптимизацией; сначала используем Debug.

## Управление

Программа запускается сразу в холле.

| Клавиша | Действие |
| --- | --- |
| A / D | Холл: рыцарь идёт влево / вправо, камера следует за ним. Фасад: камера вдоль стены |
| Левый Shift | Идти быстрее |
| W / S | Приблизить / отдалить камеру |
| ↑ / ↓ | Посмотреть выше / ниже |
| O | Общий вид всего холла |
| C | Показать ближнюю сторону холла / вернуть разрез |
| Home | Сбросить камеру холла |
| F1 / F2 | Фасад / холл |
| Escape | Выход |

## Зависимости

| Библиотека | Версия | Для чего нужна | Подключение |
| --- | --- | --- | --- |
| [GLFW](https://github.com/glfw/glfw/tree/3.4) | 3.4 | Окно, клавиатура, контекст OpenGL | CMake FetchContent, статическая сборка |
| [GLAD](https://github.com/Dav1dde/glad/tree/v0.1.36) | Генератор 0.1.36, API OpenGL 3.3 | Загрузка функций OpenGL | `third_party/glad`, исходники C |
| [GLM](https://github.com/g-truc/glm/tree/1.0.1) | 1.0.1 | Векторы, матрицы и преобразования | CMake FetchContent, заголовки |

Версии GLFW и GLM закреплены, архивы проверяются по SHA-256. Их исходники
и лицензии находятся в `out/build/<конфигурация>/_deps` после настройки.
Лицензия GLAD включена в `third_party/glad/LICENSE`.
Сгенерированный загрузчик содержит API профиля compatibility 3.3; приложение
создаёт **core**-контекст OpenGL 3.3 и использует только его функции.

## Сборка из командной строки

В **Developer PowerShell for Visual Studio** перейди в корень репозитория:

```powershell
cmake --preset windows-debug
cmake --build --preset windows-debug
```

Готовая программа: `out/build/windows-debug/bin/simple_castle.exe`.
Папки `shaders` и `assets` автоматически копируются рядом с программой при
сборке, в том числе если изменились только шейдеры. Запускай программу из
корня проекта или из папки `bin`, где находятся эти ресурсы.

Короткая проверка окна, OpenGL, шейдеров и отрисовки трёх кадров:

```powershell
./out/build/windows-debug/bin/simple_castle.exe --smoke-test
```

Эта проверка создаёт скрытое окно и завершается сама. Успех — сообщение
`Smoke test passed: 3 frames rendered.` и код возврата 0.

## Как работаем втроём

- `main` — общая проверенная версия.
- На каждую задачу создаём отдельную ветку, например `feature/pom-walls`,
  `feature/castle-scene` или `feature/key-and-gate`.
- Перед новой задачей получаем свежую версию `main` через Pull.
- После изменения: сохранить файлы → Commit → Push → Pull Request в `main`.
- Перед объединением другой участник проверяет изменения и запуск.
- `out`, `build`, `.vs` и личные настройки IDE исключены из Git.

Актуальная работа сейчас в ветке `feature/scene-foundation`: в Visual Studio
сделай Fetch и переключись на неё. Когда версия проверена, её объединяют
в `main` через Pull Request.
